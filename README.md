# マンガライブラリ管理アプリ

複数の電子書籍プラットフォーム(Kindle、DMMブックス、めちゃコミックなど)にまたがって購入したマンガを、1つの場所でまとめて管理できるWebアプリです。

## 開発の背景

複数の電子書籍サービスで漫画を購入していると、「どの作品を」「どのサービスで」「何巻まで」持っているかが分からなくなりがちです。この課題を解決するために、所有巻を一元管理できるアプリを開発しました。

## 主な機能

- ユーザー登録・ログイン機能(Laravel Breeze)
- 作品(タイトル・作者・ジャンル・表紙画像)の登録・編集・削除
- 表紙画像のアップロードとサムネイル表示(未設定の場合はプレースホルダー表示)
- 所有巻(巻数・購入プラットフォーム・購入日・既読状態)の登録・編集・削除
- 作品ごとにグループ化された所有巻一覧(アコーディオン形式で開閉可能)
- 作品タイトルによる検索(部分一致)
- 作品一覧から「巻を追加」で、その作品を選択済みの状態で登録画面へ移動
- 各巻の閲覧ページへの直接リンク(「読む」ボタン)
- 対応プラットフォーム:Kindle、DMMブックス、めちゃコミック、コミックシーモア、ピッコマ、Renta！、少年ジャンプ+、ebookjapan、楽天Kobo、ブックライブ
- ユーザーごとのデータ分離(自分の所有巻データだけを表示・編集・削除できる設計)


## 使用技術


| 分類 | 技術 |
|---|---|
| バックエンド | PHP 8.2, Laravel 12 |
| フロントエンド | Blade, Alpine.js, Tailwind CSS(独自テーマカラーを定義) |
| データベース | MySQL |
| 認証 | Laravel Breeze |
| ファイル保存 | Laravel Storage(表紙画像) |
| 開発環境 | XAMPP(Apache, MySQL) |

## データベース設計

4つのテーブルで構成しています。

- `users`:ユーザー情報(Laravel標準)
- `series`:作品マスタ(タイトル・作者・ジャンル)
- `platforms`:プラットフォームマスタ(Kindleなど)
- `volumes`:所有巻データ(ユーザー・作品・プラットフォームを外部キーで紐付け)

`series`と`platforms`をマスタテーブルとして分離することで、同じ作品を複数のプラットフォームで所有している場合にも対応できる設計にしています。

## 工夫した点

- **セキュリティ**:所有巻の編集・削除処理では、必ずログイン中のユーザーIDで絞り込んだ上でデータを取得しており、他人のデータへ不正にアクセスできないようにしています。
- **パフォーマンス**:一覧表示時にはEloquentのEagerロード(`with()`)を使用し、N+1問題を回避しています。
- **UX**:所有巻が増えても見やすいよう、作品ごとにグループ化した上でAlpine.jsによる開閉(アコーディオン)機能を実装しています。また、作品一覧から「巻を追加」を押すと該当作品が選択済みの状態で登録画面に移動するため、作品数が増えても入力の手間が増えません。
- **入力チェック**:サーバー側のバリデーションで、画像ファイルの形式・サイズや、URLの形式を検証しています。
- **デザイン**:Tailwind CSSの設定でテーマカラーを一元定義し、配色の変更を1か所で行えるようにしています。

## セットアップ方法

```bash
git clone https://github.com/acmama2526/manga-library.git
cd manga-library
cd manga-library
composer install
npm install
cp .env.example .env
php artisan key:generate
```

`.env`ファイルにデータベース情報(`DB_DATABASE`など)を設定し、MySQLにデータベースを作成した後:

```bash
php artisan migrate
php artisan db:seed --class=PlatformSeeder
php artisan storage:link
npm run build
php artisan serve
```

`php artisan storage:link`は、アップロードした表紙画像をブラウザから表示するために必要です。
